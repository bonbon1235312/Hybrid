# Hybrid MySQL 8 Port Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (\`- [ ]\`) syntax for tracking.

**Goal:** Replace Hybrid's PostgreSQL persistence with a verified MySQL 8.0.46 implementation without changing League Core behaviour.

**Architecture:** Keep the existing \`TransactionalDatabase\` service boundary, but back it with a pooled \`mysql2/promise\` adapter. Convert migrations and raw repository SQL explicitly to MySQL 8 syntax, preserving InnoDB transactions, tenant-scoped foreign keys, row locks, durable job leasing, and opaque-route single use. Run the existing behaviour suite against a disposable MySQL 8 test container.

**Tech Stack:** Node.js 24.14+, TypeScript 6, mysql2/promise, MySQL 8.0, Vitest 4, Testcontainers, Discord.js 14.

## Global Constraints

- Production supports MySQL 8.0.46 only; do not retain a PostgreSQL runtime path or add dual-engine support.
- Do not include database credentials, endpoints, \`.env\` files, or test databases in source control or release archives.
- Preserve \`/league\` and \`/help\` as the only public commands. Do not add EA, fixture, transfer, or other product scope.
- Preserve application-generated UUIDs, league tenant isolation, audit trail writes, and durable role-job semantics.
- Use InnoDB and tenant-scoped SQL predicates for every mutable operation.
- Every persisted Discord component route remains signed, actor-bound, expiry-bound, and atomically single-use.
- Tests run only against an isolated disposable MySQL 8 schema/container; never point \`HYBRID_TEST_DATABASE_URL\` at a live bot database.
